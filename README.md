# RENAME / FIELD

**같은 값, 더 분명한 이름.** 가상의 카페 주문 데이터에서 `amt`를 `totalAmount`로 바꾸며 Rename Field를 배우는 한국어 인터랙티브 튜토리얼입니다. 객체의 필드, 객체를 가리키는 변수, 화면의 표시 문구를 구분하고, 데이터를 만드는 곳과 읽는 곳의 이름을 함께 맞춥니다.

실행: [GitHub Pages에서 튜토리얼 열기](https://technoetic.github.io/rename-field-tutorial/). 정적 파일만 제공하며 별도 서버나 계정이 필요하지 않습니다.

## 학습 화면

| 주소 | 내용 |
|---|---|
| `#/` | 같은 값 10000, 더 분명한 이름을 직접 눌러 비교 |
| `#/story` | 카페 주문 한 건으로 필드 이름의 의미 이해 |
| `#/lab` | 새 이름 입력, 생성 코드·영수증·보고서 맞추기 |
| `#/contract` | 기존 키·새 키·임시 이중 키의 소비자 호환성 비교 |
| `#/practice` | 객관식 6문제, 해설, 선택 메모와 저장 |
| `#/code` | 실제 객체 코드의 변경 전후와 같은 출력 확인 |
| `#/summary` | 적용 체크리스트와 원전 |

각 해시 주소를 북마크하거나 공유할 수 있습니다. 알 수 없는 화면 주소에는 돌아가기 안내를 보여 줍니다. 키보드 조작, 밝은·어두운 테마와 움직임 줄이기를 지원합니다.

## 저장과 개인정보

실험 화면의 필드 이름·스위치 상태와 연습 답·메모는 **저장을 누르면 현재 브라우저의 localStorage에만** 각각 저장합니다. 답과 메모를 서버로 전송하거나 다른 기기와 동기화하지 않습니다. 브라우저 데이터를 지우거나 다른 주소·기기를 사용하면 저장한 내용을 이어 볼 수 없습니다.

저장하지 않은 변경이나 진행 중인 저장이 있으면 화면 이동과 업데이트를 보호합니다. 저장 실패를 성공으로 표시하지 않으며, 저장 중 새로 편집한 내용은 미저장 상태로 남습니다. 연습 초기화는 확인 후 연습 답과 메모를 지웁니다. 실험 저장 내용은 별도로 유지됩니다.

## 로컬 실행

Node.js **22 이상**이 필요합니다. 외부 패키지 설치 없이 실행합니다.

```sh
npm start
npm test
npm run build
```

`npm start`는 빌드 후 <http://127.0.0.1:8816/rename-field-tutorial/>에서 제공합니다. 포트가 사용 중이면 중단합니다. 다른 포트는 `node scripts/server.mjs --port 8817`로 지정합니다. `npm test`는 Node 기본 테스트 러너를 사용하고, `npm run build`는 GitHub Pages에 제공할 정적 파일을 `dist/`에 만듭니다.

## 구조와 여섯 가지 원칙

| 원칙 | 구현 |
|---|---|
| 책임에 따라 파일 분리 | `src/screens/`, `services/`, `tutorial/`, `shared/`와 계층별 `styles/` |
| 화면과 상태를 클래스로 관리 | 공통 `Screen`, 화면별 클래스, 저장·라우터·버전 서비스 |
| 데이터를 비동기로 로드 | `data/*.json` 검증, 로딩·오류·재시도, 취소 및 오래된 응답 차단 |
| 화면에 고유 주소 부여 | 해시 라우팅, 직접 진입, 뒤로·앞으로 이동 |
| 자산과 데이터의 캐시 구분 | 빌드 ID를 붙인 자산, 새 JSON 요청, 이전 배포 자산 보존, 없는 자산은 404 |
| 열린 탭도 안전하게 갱신 | 새 빌드·롤백 감지 후 다음 안전한 화면 이동에서 전체 문서 갱신, 작성 내용과 저장 중 상태 보호 |

데이터 내용만 바뀌면 빌드 ID는 유지됩니다. 서비스 워커나 별도 API 서버는 없습니다. GitHub Pages의 캐시 때문에 새 배포가 즉시 보이지 않을 수 있습니다.

## 학습 범위와 출처

이 실험은 가상의 JavaScript 객체를 다룹니다. 실제 API·데이터베이스·스키마를 변경하지 않습니다. 외부 소비자와의 전환은 예시로 보여 주며, 실제 적용에는 별도의 호환성·마이그레이션 계획이 필요합니다. 모든 곳에서 같은 값을 읽는다고 이름의 의미까지 적절하다는 뜻은 아닙니다.

원전: [Martin Fowler — Rename Field](https://refactoring.com/catalog/renameField.html). 카페 이야기와 예제 코드는 이 튜토리얼을 위해 새로 작성했습니다. Martin Fowler나 출판사와 관계없는 독립 교육 자료입니다.
